Add DBR data fields to Case Details (manual entry)

Mohit (fields) ILIA dev No dependencies
Why now

The processing team is handling DBRs manually and has nowhere in Case Details to record the data. Adding these fields as simple, editable inputs solves that immediately — independent of the carrier scraper, election capture, and status automation (all later in the Epic).

Scope
  • Add a Death Benefit Reduction section to the Case Details tab, under Benefit Amounts.
  • Fields are manually editable by admin / processing and persist on the case record.
  • Fields to add: start year, current DB, term/base DB, Full/Half/No amounts, low point per option, low cash value, income, DB at age 90, in-force rate, DBR status, elected option, election date. (See the screen →)
Out of scope (keeps it small)
  • No scraper / auto-population
  • No election capture or DocuSign
  • No status workflow / calculations
Acceptance criteria
  • The DBR fields appear in Case Details under Benefit Amounts.
  • Processing can enter, edit & save each value.
  • Values persist and display on the case.
Note

This is a subset of the DBR-automation Case Details work — later these same fields get auto-populated by the scraper + election. Building them now as manual fields unblocks processing without rework.
